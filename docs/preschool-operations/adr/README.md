# Architecture Decision Records

ADRs retain **why** Bcube made an important operating, academic, design or technology decision.

## When to create an ADR

Create one when a decision materially affects:

- preschool operating model
- curriculum / academic architecture
- child safety or safeguarding controls
- technology or data architecture
- branch standardization
- publishing/design architecture
- significant vendor/platform selection
- a standard that would be expensive or risky to reverse

## Naming

`ADR-0001-short-decision-title.md`

## Template

```markdown
# ADR-0001 — Decision title

**Status:** Proposed | Accepted | Superseded | Rejected  
**Date:** YYYY-MM-DD  
**Owner:** <Role>

## Context
What problem are we solving?

## Decision drivers
- ...

## Options considered
### Option A
### Option B
### Option C

## Decision
What was selected?

## Rationale
Why was it selected?

## Consequences
### Positive
### Negative / trade-offs

## Follow-up
What must happen because of this decision?
```
